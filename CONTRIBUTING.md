# Contributing

Thanks for taking the time to improve **YouTube Bot Comments Filter**.

This document covers setup, conventions, and what a pull request needs to pass
review and CI. For vulnerability reports, follow [SECURITY.md](SECURITY.md)
instead of opening a public issue.

## Before you start

- **Bugs and feature ideas** — open a
  [GitHub issue](https://github.com/NemoKing1210/youtube-bot-comments-filter/issues)
  with the script version, userscript manager, browser, and steps to reproduce.
- **Larger changes** (new detection signals, UI changes, refactors) — open an
  issue first so the approach can be agreed on before you write code.
- **Small fixes** (typos, docs, obvious bugs) — a direct pull request is fine.

## Requirements

- [Node.js](https://nodejs.org/) **22** (see [`.nvmrc`](.nvmrc)) and npm
- A userscript manager for manual testing:
  [Tampermonkey](https://www.tampermonkey.net/),
  [Violentmonkey](https://violentmonkey.github.io/), or
  [ScriptCat](https://scriptcat.org/)

## Setup

```bash
git clone https://github.com/NemoKing1210/youtube-bot-comments-filter.git
cd youtube-bot-comments-filter
npm install
npm run dev
```

`npm run dev` starts Vite and serves an installable userscript named with a
`dev:` prefix. Install it once in your userscript manager; changes under `src/`
are applied with HMR while the server runs.

To test a production build instead:

```bash
npm run build
```

then install the root `youtube-bot-comments-filter.user.js`.

## Project structure

```text
src/
├── main.js                 # Bootstrap / init
├── constants.js            # Storage keys, thresholds, icon paths
├── settings.js             # getMode / setMode (GM storage)
├── i18n/                   # LOCALES + t()
├── detection/              # RULES + BotDetector
├── styles/                 # CSS (injected via vite-plugin-monkey)
└── features/               # Comments, account-menu settings, observer
scripts/                    # Build helpers (copy-dist, verify-artifacts)
vite.config.js              # Userscript metadata + Vite config
```

**Edit `src/`. Never hand-edit the committed
`youtube-bot-comments-filter.user.js` / `.meta.js`** — they are build output
and are regenerated by `npm run build`.

## Conventions

- Vanilla JavaScript ES modules only. Do **not** add TypeScript or a frontend
  framework unless it was explicitly requested in an issue.
- Import GM APIs from `$` (`vite-plugin-monkey/dist/client`) and keep `@grant`
  minimal; declare new grants in `vite.config.js`.
- Put constants in `src/constants.js`, user-facing strings in `src/i18n/`,
  UI hooks in `src/features/`, and detection logic in `src/detection/`.
- Prefix CSS classes with `ytbf-` and storage keys with `ytbf_`.
- Userscript metadata (names, descriptions, `@match`, update URLs) lives in
  `vite.config.js`. Never commit temporary localhost `@updateURL` /
  `@downloadURL` values.
- Style UI with YouTube CSS variables (`var(--yt-spec-*)`) and check both light
  and dark themes.
- Keep the diff focused. Avoid unrelated reformatting.

## Extending bot detection

Detection is nickname-based by design — do not change it to parse comment text
without discussing it in an issue first.

- Add exact spam substrings to `EXACT_MATCHES` in `src/constants.js`.
- Add abused TLDs to `SPAM_TLDS` in `src/constants.js`.
- Push new rule objects into `RULES` in
  [`src/detection/bot-detector.js`](src/detection/bot-detector.js). Each rule
  has a `name`, a `weight`, and a `test(name)` function. The default flag
  threshold is `THRESHOLD = 4`.
- Prefer weighted heuristics over brittle catch-all regexes. A rule that flags
  normal usernames is worse than a missed bot.
- Test against real-looking normal nicknames as well as spam examples.

## Localization

The UI ships in `en`, `ru`, `es`, `fr`, `de`, `pt`, `zh`, `ja`, `ar`, `hi`
(browser locale, English fallback).

- Add every new user-facing string to **all** `LOCALES` entries in
  [`src/i18n/locales.js`](src/i18n/locales.js).
- Keep localized `@name` / `@description` in `vite.config.js` aligned when the
  product description changes.

## Build and verification

```bash
npm run dev              # Vite dev server + HMR
npm run build            # Build dist/ and copy artifacts to repo root
npm run ci               # Exactly what GitHub Actions runs
npm run verify:artifacts -- --git   # Also require committed artifacts to match HEAD
```

- `npm run build` must be run before committing when source or metadata
  changes. CI fails if the committed root artifacts are stale.
- `npm run ci` locally checks `dist/` ↔ root consistency; add `--git` (or set
  `CI=true`) to reproduce the full CI freshness check.

## Pull request checklist

- [ ] Changes are made in `src/` (or docs/config), not in built artifacts
- [ ] `npm run build` was run and the regenerated root
      `youtube-bot-comments-filter.user.js` / `.meta.js` are committed
      (when the change affects the shipped script)
- [ ] `npm run ci` passes
- [ ] New user-facing strings exist in all supported locales
- [ ] README translations (`README.<lang>.md`) updated when user-visible docs change — English `README.md` stays canonical
- [ ] No localhost `@updateURL` / `@downloadURL` values
- [ ] `CHANGELOG.md` has an entry for user-visible changes
- [ ] `package.json` `version` bumped when preparing a release
- [ ] README badges / docs updated if behavior or version changed
- [ ] Manual check on a YouTube watch page: hide and blur modes, account-menu
      settings, SPA navigation, light and dark themes

Conventional-style commit messages (`feat:`, `fix:`, `docs:`, `chore:`) are
appreciated but not enforced.

## Maintainer notes

When shipping a user-visible change:

1. Bump `version` in [`package.json`](package.json) — it is the single source
   of truth for `@version` and `SCRIPT_VERSION`.
2. Run `npm run build`.
3. Add a [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) entry under a
   new version heading in [`CHANGELOG.md`](CHANGELOG.md).
4. Update the README version badge and any behavior docs.
5. Commit the source change and the regenerated artifacts together.
